## GA4 啟用規格

網站以單一 Google tag 安裝，沒有 GTM 或第二套追蹤。`NEXT_PUBLIC_GA_MEASUREMENT_ID` 留空時不載入分析；僅正式 production build、hostname 精確為 `suzuki-taipei.com` 且 ID 格式有效時啟用。本機／預覽即使有 ID 也不啟用。

正式啟用順序（需取得正式設定及部署授權）：

1. 唯讀核對是否已有本站 GA4 property／Web data stream；沿用適合的既有資料串流，不重複裝標籤。若尚無資料串流，由管理者建立並提供 Measurement ID；不需要提供私人 API 金鑰。
2. 資料串流關閉 Enhanced measurement 的自動頁面變更、表單、外連等蒐集；本站自行送事件。程式已設定 `send_page_view: false`，並關閉 Google signals／廣告個人化訊號。
3. 設定時區 Asia/Taipei，將 `generate_lead` 標記為主要事件；計數方式採每次事件，程式自行依收件 ID 去重。`line_click` 與 `phone_click` 只列意向，不標成有效諮詢。
4. 如需自訂維度，建立事件範圍的 `car_id` 與 `entry`。使用既有頁面路徑、著陸頁與工作階段來源維度，不建立案件 ID 維度。
5. 先核對資料串流設定，再在正式環境設定 Measurement ID 並發布。啟用前的 GA4 數據標為「未啟用」，不能補推為零或回填歷史事件。
6. 發布後核對瀏覽、站內導覽、LINE／電話點擊及 DebugView。真實收件事件等待自然案件確認；主動全鏈路表單測試需另行授權。

| 事件 | 觸發 | 用途 |
| --- | --- | --- |
| `page_view` | 首次載入及已知內容頁 pathname 變更；錨點、查詢參數、彈窗與照片切換不加計 | 內容瀏覽 |
| `line_click` | LINE 連結點擊，包括原首頁、彈窗及手機列 | 聯絡意向 |
| `phone_click` | 電話連結點擊 | 聯絡意向 |
| `directions_click` | 地圖連結點擊 | 到店意向 |
| `consultation_click` | 前往表單或彈窗「我有興趣」 | 表單入口 |
| `generate_lead` | HTTP 成功、`ok=true`、receipt 與本次 UUID 相符 | 已持久收件 |

事件欄位只允許 `car_id`、`entry` 與清洗後的頁面資訊。`car_id` 只允許六個既定 ID，其餘為 `unspecified`；`entry` 為已知介面位置。頁面路徑只允許 12 個內容頁；移除 query／hash，外站 referrer 只保留網域。不傳姓名、電話、表單內容、原始錯誤或 UUID，分析失敗不影響表單。

UUID 只在前端記憶體用於去重，未變更的失敗重試及站內切頁沿用 UUID。通知故障但已持久保存仍算收件成功；503、429、連線中斷或 receipt 不符都不算成功。硬重新整理會清掉記憶體中的草稿及本機事件去重狀態；私人持久收件是最終案件依據。
